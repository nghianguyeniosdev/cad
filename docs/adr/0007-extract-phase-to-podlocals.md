# 7. Extract Phase — unzip into PodLocals (versioned layout)

Date: 2026-07-09

## Status

Accepted. Partially supersedes ADR 0006 (the "acd never extracts" boundary).

## Context

ADR 0006 drew a hard line: `acd` downloads the archive and keeps it as-is;
unzipping happens downstream in the iOS repo. In practice the iOS workflow's
downloader (`iosPrepareArtifact.sh`, and the newer Ruby generated by
`Podfile+Builder.swift`) always does download **and** extract in one shot —
nobody runs a separate extract by hand. Requiring two tools for what is
conceptually one `pod install`-style step is friction we chose to remove.

Scope of *this* phase is deliberately narrow: **download + faithful unzip into
`PodLocals`**. The iOS-specific fussing the current scripts also do — requiring a
`.podspec` to exist, and `patch_podspec_arm64` (stripping
`EXCLUDED_ARCHS[sdk=iphonesimulator*]`) — is **explicitly deferred** to a later
planning round, along with the broader question of migrating off / replacing the
`.sh`/`.rb`.

## Decision

Add an **Extract Phase** as the third phase of a run (Enumerate → Download →
Extract), coupled to Versioned Layout:

- **`layout: versioned` ⇒ always extract.** No new flag or key. Versioned layout
  *is* the iOS pods workflow, so it downloads to the Cache Root and then extracts
  to `PodLocals`. Flat layout never extracts. There is no cache-only variant.
- **Runs after Download completes** and only for packages present in the cache
  (a package whose download failed is already a Download failure; Extract does
  not run for it).
- **Source:** exactly one `.zip` asset in the pinned version's Cache Root folder
  (`<cache_root>/<package>/<pinned-version>/<one>.zip`). Zero or >1 `.zip` for a
  package is a hard error for that package. Extraction always uses the version
  pinned in `codeartifact.yaml`, never another version left in the cache.
- **Destination:** hardcoded `./PodLocals/<package>/Current`, relative to the
  working directory (the iOS repo root). No configuration. Running from the wrong
  directory fails clearly rather than writing somewhere surprising.
- **Clean extraction:** `Current` is wiped and re-created before unzip, so it
  always holds exactly the pinned version's contents and nothing acd-owned leaks
  inside it.
- **Idempotency via an Extraction Marker.** After a successful extract, write
  `PodLocals/<package>/.acd-version` (a *sibling* of `Current`, never inside it)
  holding the pinned version plus a **fingerprint** — a hash over the sorted
  `(relative-path, size)` of every file in `Current`. On the next run: version +
  fingerprint match ⇒ **skip** ("already extracted"); any mismatch (wrong
  version, or a deleted / added / renamed / truncated file) ⇒ **wipe and
  re-extract**. The walk is stat-only; file contents are never re-hashed.
- **Failure handling:** per-package failures are collected, the phase continues,
  and they are listed in the Run Summary with a non-zero exit — same model as
  Download failures. A failed package's `Current` is left empty and no marker is
  written, so the next run retries it automatically.
- **Concurrency** reuses the existing download worker pool / `--concurrency`.

## Considered Options

- **Separate `acd extract` subcommand / `--extract` flag** — rejected for the
  headline UX in favour of the one-command `pod install` feel (download finishes,
  Extract Phase starts). A standalone extract primitive may still be added later
  for offline re-extract; not in this phase.
- **Prevent tampering with `Current`** (read-only / `chflags uchg`) — rejected.
  CocoaPods/Xcode and users legitimately touch that folder; locks get bypassed
  and cause confusing failures. We detect-and-heal instead.
- **Marker granularity: version-only vs. path/size fingerprint vs. full content
  hashes** — chose path/size fingerprint. Version-only is blind to manual
  deletion inside `Current`; full content hashing is too slow on large
  `xcframework` binaries for the no-op path. Fingerprint catches
  deletes/adds/truncation cheaply; the known gap is an in-place edit that
  preserves file size.

## Consequences

- A "downloader" now writes unpacked files into the iOS repo's `PodLocals` — the
  ADR 0006 boundary is intentionally relaxed for versioned layout only.
- `Current` is guaranteed to match the pinned version; a version bump in the
  manifest forces a clean re-extract automatically.
- iOS-specific extraction concerns (`.podspec` requirement, arm64 patch) are
  **not** handled yet — a manifest that relies on those still needs the existing
  script until a follow-up phase brings them in (or decides they stay downstream).
